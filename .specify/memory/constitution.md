# 知行智学软件架构 SDD/TDD Constitution

## Core Principles

### I. 业务真实路径优先
任何模块必须从真实学习场景出发：手机兴趣、PC 自主学习、纸笔/教材学习均为独立入口。禁止把手机到 PC、设备到结论或采集到干预画成默认因果链。

### II. 证据先于解释
每个解释必须引用会话、时间窗口和证据索引；事实与解释字段分离。证据缺失、冲突或质量不合格时必须降级为记录或人工复核。

### III. 本地可信与最小必要
授权、来源过滤、同步、索引和质量门控必须优先在 PC 本地完成。敏感原始数据默认不出域；撤回必须删除原件、缓存、任务、索引和派生结果。

### IV. TDD 不可跳过
任何生产功能必须先有可执行的失败测试；按 Red → Green → Refactor 推进。涉及设备、同步、删除和证据引用的改动必须包含契约测试与端到端验收。

### V. 可替换而不改写业务
参赛期本地闭环与后续云端扩展必须复用事件协议、证据 URI、权限模型和审计语义。云端只能替换计算/存储部署，不能改变两条业务闭环。

## Additional Constraints

状态设备只提供趋势、连续性和质量线索，不输出医学、心理、能力或确定性专注度结论。快路径不能产生知识结论、证据卡或微任务；慢路径必须使用完整连续媒体及其可核验上下文。

## Development Workflow

每个特性必须维护规格、数据模型、接口契约、测试设计、实施计划和任务清单；评审先检查需求追溯，再检查实现。未经真机或样本验证的能力必须标为“待验证”。

## Governance

本 Constitution 高于后续实现习惯。任何修改必须说明对业务闭环、数据边界、测试与审计的影响，并同步审查所有规格工件。版本遵循语义化版本；架构或证据原则变更为 MAJOR，新增强制规则为 MINOR，澄清为 PATCH。
