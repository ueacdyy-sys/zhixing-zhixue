# 知行智学算法创新边界（锁定）

## 目标

竞赛主创新定位为可训练的算法系统，而不是将 OCR、ASR、多个 VLM 的结果并列展示，也不是以 UI 或业务流程替代模型创新。

目标任务为：在连续中文手机屏幕流中，对每个带 PTS 的视频窗口生成可验证的内容理解结果（主题、时间范围、证据区域、证据文本与不确定性）。该任务不直接从视频推断学生兴趣、能力、专注或心理状态。

## 第一层：时序多 VLM 专家协同网络

暂定研究名称：`TME-MoE`（Temporal Multi-Expert Mixture of Experts）。

输入是同一窗口的完整视频、对齐 ASR、跨帧 OCR 轨迹、UI 布局特征和 PTS。模型包含至少三种可区分的专家能力：

- 中文视频语义专家：理解画面、字幕和知识主题；
- UI/内容边界专家：区分平台控件、评论/广告、视频内字幕和真实内容；
- 时序音视一致性专家：判断 ASR、OCR 和视频画面是否支持同一 PTS 范围内的结论。

专家输出统一的带时间和区域锚点的证据单元。可训练 Router 根据 UI 污染、跨模态一致性、时间连续性、输入质量和任务难度选择/加权专家；融合器显式处理支持、冲突和拒答。

硬要求：

- 不以固定 if/else、置信度最大值或模型投票冒充 Router；
- 不把多家 API 的回答拼接后宣称为模型创新；
- 必须定义专家、Router 和融合器的训练目标，并与单 VLM、固定融合、投票融合做消融；
- 输出必须绑定到 PTS、源媒体哈希与证据区域；
- 只能输出内容证据/学习机会窗候选，不能直接输出兴趣结论。

## 第二层：流式视觉 KV Cache 优化

暂定研究名称：`Evidence-Aware Visual KV Cache`。

KV Cache 是 Transformer 对已处理 token 的 Key/Value 张量缓存，不是可手工编辑的“理解文件”。不得直接篡改张量以控制答案。优化对象是：哪些文本 token、视觉 token 和跨窗口历史 token 被保留、压缩、量化、分页、复用或淘汰。

本层针对连续视频的核心假设：对当前窗口真正有帮助的历史缓存，应同时满足时间相邻性、跨模态证据一致性和非平台 UI 属性；高频但无语义价值的平台 UI token 不应长期占用缓存。

候选机制：

- 为每个 visit 独立维护视觉/文本缓存，visit 结束强制隔离与清空；
- 将 attention、时间新鲜度、OCR/ASR/VLM 一致性和 UI 噪声预测合成为可学习的 token 保留分数；
- 保留锚点 token、近期 token 与高证据 token，对低价值 token 做选择性压缩/低比特量化/分页换出；
- 当新窗口与历史窗口存在语义延续时复用缓存，否则回退为完整窗口推理；
- 将 Router 的专家选择与缓存预算共同训练或共同评价，避免只追求吞吐而损失内容理解。

硬要求：

- 不把 KV Cache 命中率、显存下降或 token/s 提升单独写成“理解提升”；
- 必须同时报告主题理解、时间定位、UI 误识别、拒答校准、p50/p95 延迟、显存与缓存命中率；
- 必须与无缓存、FIFO/LRU 缓存、StreamingLLM/H2O 类启发式缓存、固定视频 token 采样做对比；
- 缓存不得跨用户、跨视频会话或跨访问权限复用。

## 当前代码事实与研究起点

当前 VLM 基线只有 `HuggingFaceTB/SmolVLM2-500M-Video-Instruct`：每个窗口最多采样 4 帧，英文单句提示，输出仅为 `raw_model_text`。它只能作为单 VLM 基线，不得称为上述两层算法的完成实现。

## 文献锚点

- MoE-LLaVA（多专家视觉语言模型）；
- VideoLLaMA 2（视频时空与音频理解）；
- VTimeLLM / TimeChat / UniVTG（视频时间定位）；
- ScreenAI / Ferret-UI / BOVText（UI 与跨帧文本）；
- StreamingLLM、H2O、SnapKV、PagedAttention、LOOK-M（流式/多模态 KV Cache 管理）。

最终论文创新性必须在完成针对上述工作的系统性文献对比后确认；本文件锁定的是研究边界和不可退化约束，而不是预先宣称 SOTA。
