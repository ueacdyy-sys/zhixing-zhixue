# 审查入口

建议审查顺序：

1. `specs/001-multi-entry-learning-evidence/architecture.md`：先判定业务路径是否被错误线性化。
2. `spec.md`：核对需求、验收与边界。
3. `data-model.md` 与 `contracts/`：核对可追溯性、删除与卡片约束。
4. `plan.md`：核对参赛期与升级域边界。
5. `tasks.md` 与 `docs/tdd/test-matrix.md`：核对是否真正按 TDD/SDD 推进。

本轮重点审查问题：手机日常碎片化内容场景是否被明确为 MVP 主闭环；PC 是否从第一阶段承担分析中枢、证据工作台和结果回传，并在第二场景承担学习发生端与学习流采集端；手机是否被错误设置为 PC 学习的前置条件；状态设备是否被越界写成诊断设备。
