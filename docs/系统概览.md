# 知行智学系统概览

本文档从用户视角、功能视角和技术视角三个层面完整描述知行智学系统的设计思路、实现状态和技术路线。

---

## 一、用户视角：系统为谁解决什么问题

### 1.1 核心用户群体

**学习者(学生)**
- 遇到兴趣内容(短视频、科普、电影解说)时,不知道如何转化为学习任务
- 学习过程中频繁卡顿、切换、放弃,不清楚问题出在哪里
- 学习完成后只看到结果分数,缺少可回溯的过程证据

**教师**
- 只能看到作业结果和考试成绩,无法获得学生自主学习的连续证据
- 难以判断学生在哪个环节需要引导,在哪里真正理解了
- 过程性评价缺少可复查的客观材料,容易依赖主观印象

**研究者/验证人员**
- 需要小样本、可控、合规的学习分析样例
- 需要验证AI教育应用的可解释性和可追溯性

### 1.2 要解决的核心问题

**问题1: 学习启动断裂 - 兴趣无法进入学习**
学生在日常娱乐时间(刷短视频、看电影解说、科普内容)会遇到很多有价值的概念、表达和问题,但这些兴趣点**几乎从不会**被转化为学习任务。

**为什么不会主动学习?**
- 娱乐状态下,学生不愿意被系统强行拉入正式学习
- 没有明确的学习目标和可执行任务
- 不知道从哪里开始、需要多长时间、能不能放弃

**系统需要做什么?**
识别兴趣中有价值的内容,生成**可接受、可延后、可关闭、可反馈**的微学习任务,让学习从真实生活入口自然发生,而不是强制打断。

**问题2: 过程证据断裂**
即使学生接受了微任务并进入学习,手机、PC、纸笔、视频、EEG/EDA等数据各自孤立,缺少统一的事件字段和时间轴。学习者和教师看不到完整的学习过程线索。

**问题3: 复盘解释断裂**
学习者只看到结果和建议,看不到"系统为什么给出这个建议"、"证据是否充分"、"我在哪个时间窗口发生了策略变化"。

### 1.3 用户使用场景

**核心场景: 从兴趣到学习的完整链路(这才是真实场景!)**

**阶段1: 兴趣触发(手机端,日常娱乐状态)**
- 学生在手机上刷短视频、看电影解说、科普内容、热点讨论
- **不是在学习,而是在娱乐、放松、随便看**
- 遇到一个陌生词语、新概念、有趣表达、观点冲突、人物评价
- 系统记录: 停留时长、复看次数、收藏、搜索、主动提问

**阶段2: 兴趣桥接(系统识别,轻量建议)**
- 系统识别兴趣内容中有价值的概念/表达/问题
- 生成目标明确、时长有限的微学习任务
- **重点: 可接受、可延后、可关闭、可反馈**
- **不强制、不打断、不把娱乐变成学习任务**

**阶段3: 学习承接(如果学生接受)**
- 学生**可能**转到PC查资料、整理素材、写笔记
- **可能**拿出纸笔书写例句、阅读课本
- **可能**观看教学视频、完成小练习
- 系统采集: PC窗口、网页、笔记、视频片段(如果有摄像头/眼镜)
- 状态趋势: EEG/EDA等可选设备(如果接入)

**阶段4: 过程记录与机会窗识别**
- 系统记录: 何时进入、何时卡顿、何时切换资料、何时恢复
- 识别学习机会窗: 启动、卡顿、策略切换、恢复、复盘
- **不是监控,而是记录学习过程的关键转折**

**阶段5: 复盘与证据卡**
- 任务结束后(或学生主动放弃时),生成证据卡
- 证据卡内容:
  - 学习时间线: 从兴趣到任务、从卡顿到恢复
  - 关键转折: 在哪个时间窗口发生了什么
  - 证据来源: 手机兴趣事件、PC行为、视频片段、自评
  - 复盘建议: 下次如何调整(可追溯到具体证据)

**真实样例**:
> 小明在抖音上看到一个电影解说视频,其中提到"叙事结构"和"视角转换"  
> → 系统识别: 这两个词与语文写作相关  
> → 系统生成微任务: "了解叙事结构的3种类型(5分钟)"  
> → 小明点击"接受",系统推送简短材料  
> → 小明转到PC上查资料、整理笔记  
> → 系统记录: 搜索词、停留页面、笔记修改  
> → 小明在理解"倒叙"时卡住,搜索了"倒叙和插叙的区别"  
> → 系统识别: 卡顿窗口,知识缺口是"叙事手法区分"  
> → 任务结束后,证据卡显示: 从兴趣(电影解说)→知识缺口(叙事手法)→资料检索→理解卡顿→策略调整(搜索对比)→完成笔记

**场景2: 教师过程性评价(待实现,低优先级)**
- 教师查看学生的学习任务证据卡
- 看到学生在哪里卡住、用了什么策略、是否需要引导
- 添加批注、修改复核状态
- 将证据卡作为过程性评价的客观材料

### 1.4 用户价值

**对学习者(核心价值)**
- **降低学习启动门槛**: 从娱乐内容中自然进入学习,不被强制打断
- **看到学习过程**: 理解自己如何进入学习、如何波动、如何恢复,而不是只看到成绩
- **理解困难位置**: 知道在哪个具体时间窗口卡住,而不是模糊的"能力不足"
- **获得可执行建议**: 得到具体的下一步行动(回看第2段/补充资料/求助教师),而不是"提高注意力"这种泛化建议
- **自主控制权**: 可以接受、延后、关闭微任务,不被系统绑架

**对教师**
- 获得可复查的过程材料,减少主观猜测
- 看到学生的努力、困惑和策略变化,而不只是结果
- 用证据支撑过程性评价

**对教育AI应用**
- 提供可解释、可追溯、可复核的AI教育应用范式
- 让AI建议有证据来源,避免黑箱评价
- 通过降级机制处理不确定性,而不是强行给出结论

### 2.4 证据分级机制

系统采用严格的证据分级,避免过度推断:

- **CANDIDATE_ONLY**: 单帧/OCR/无音频/时间不连续,只保留记录,不生成学习结论
- **SEMANTIC_ANALYSIS_PENDING**: 完整媒体进入慢路径分析
- **FUSION_ELIGIBLE**: 高质量模态,可参与融合
- **RECORD_ONLY**: 低质量模态,只记录不融合
- **EXCLUDED**: 质量极差,只保留质量日志

### 2.5 降级机制(四级)

**一级(全证据解释)**
- 兴趣流 + 学习流 + 视频 + 状态趋势

**二级(行为+视频)**
- 移除低质量生理信号

**三级(行为+任务上下文)**
- 移除视频

**四级(记录型证据卡)**
- 只保留事件和自评,不生成自动建议

## 三、技术视角:系统如何实现

### 3.1 技术架构栈

**前端**
- React 19.2.7 + TypeScript 5.9.2
- Vite 8.2.0 (Rolldown打包器)
- 实时仪表盘 + 时间线可视化

**后端**
- Python 3.12
- 本地优先存储(DuckDB/Parquet/JSON)
- 70项测试覆盖(pytest 9.1)

**多端采集**
- PC: Windows前台窗口API
- Android: RTSP媒体传输
- (待接入) 摄像头/眼镜: OpenCV/MediaPipe
- (待接入) EEG/EDA: BrainFlow/MNE/NeuroKit2

**时间同步**
- 系统时间戳 + 手动同步标记
- (可选) LSL多流同步
- 离线校准算法

### 3.3 核心模块实现

#### 模块1: PC任务工作台(`pc/task_workbench.py`)

**功能**:创建PC独立学习任务,不依赖手机前置

**核心函数**:
- `create_pc_task_session()`: 创建任务会话
- `add_pc_task_phase()`: 添加学习阶段
- `record_pc_learning_behavior()`: 记录学习行为
- `record_pc_environment_fact()`: 记录环境事实(前台窗口)

**验证规则**:
- 任务必须来自PC(source='pc')
- 会话和任务边界严格校验
- 证据URI必须使用`local://pc/`前缀

#### 模块2: 工作台运行时(`pc/workbench_runtime.py`)

**功能**:PC工作台的本地用例编排

**核心类**: `PCLearningWorkbenchRuntime`

**核心方法**:
- `start_task()`: 启动任务并开始采样循环
- `switch_phase()`: 切换学习阶段
- `capture_foreground_once()`: 采集一次前台窗口
- `stop_task()`: 停止任务
- `dashboard()`: 生成仪表盘数据

**采样机制**:
- 默认1秒采样间隔
- 后台线程持续采集
- 窗口指纹去重(避免重复记录)

#### 模块3: 前台窗口采集(`pc/foreground_capture.py`)

**功能**:Windows前台窗口探测

**采集内容**:
- 窗口句柄(window_handle)
- 进程ID(process_id)
- 进程路径(process_path)
- 窗口标题(window_title)
- 窗口类名(window_class)

**质量标记**:
- 进程路径不可用时标记`process_path_unavailable`

#### 模块4: 质量门控(`quality/modality_gate.py`)

**功能**:低质量模态的保守融合门控

**核心函数**:
- `assess_modality_quality()`: 评估模态质量
- `create_downgrade_log()`: 创建降级日志

**质量判断**:
```
连接状态 + 信号质量 + 证据完整性 + 时间对齐残差
  ↓
FUSION_ELIGIBLE / RECORD_ONLY / EXCLUDED
  ↓
允许操作 / 禁止操作清单
```

**可穿戴设备特殊约束**:
- 禁止能力判断(ability_claim)
- 禁止注意力诊断(attention_diagnosis)
- 禁止医学判断(medical_claim)
- 禁止心理判断(psychological_claim)

#### 模块5: 手机媒体准入(`analysis/slow_path.py`)

**功能**:连续媒体语义分析的保守准入门

**核心函数**: `admit_full_segment()`

**准入条件**(全部满足):
1. 有capture_id
2. 有连续媒体URI(`media_uri`)
3. 有同源音频URI(`audio_uri`)
4. 有时区感知的时间范围(`start_ts`, `end_ts`)

**不满足时**: `BLOCKED_INSUFFICIENT_EVIDENCE` + 原因列表

#### 模块6: 时间轴对齐(`timeline/aligner.py`)

**功能**:构建PC任务时间轴

**核心函数**: `build_pc_timeline()`

**输出结构**:

#### 模块7: 学习工作门控(`learning/l0_l4_gate.py`)

**核心函数**: `gate_mobile_learning_offer()`

**规则**:

- 请求学习工作时抛出异常

### 3.4 待实现的核心算法

#### 算法1: 学习机会窗识别(核心创新,待实现)

**输入特征**:
- 兴趣强度(搜索、停留、复看、收藏、主动提问)
- 知识相关度(课程标准、题库标签、任务材料)
- 学习缺口价值(薄弱知识点、近期错误)
- 状态可接受度(自评、视频、EEG/EDA趋势)
- 行为波动(窗口切换、停顿、回看、修改、求助)
- 打扰成本(时间场景、历史拒绝、任务紧迫度)

**评分公式(待确定)**:
```
WindowScore = 兴趣强度 × 知识相关度 × 学习缺口价值 
              × 状态可接受度 - 打扰成本
```

**需要研究的方向**:
1. **认知负荷理论**:如何判断当前是否适合启动新任务
2. **心流理论**:如何识别学习进入最优体验状态
3. **推荐系统**:借鉴抖音/快手的用户行为反馈机制
4. **自我调节学习理论**:如何识别策略切换和元认知

**窗口类型**:
- 启动窗口(学习入口)
- 卡顿窗口(需要帮助)
- 策略切换窗口(方法调整)
- 恢复窗口(有效策略)
- 复盘窗口(总结反思)

#### 算法2: 兴趣-知识桥接(待实现)

**输入**:
- 兴趣标签(从内容、搜索、收藏中提取)
- 课程知识点库
- 学生当前学习目标

**输出**:
- 目标明确的微学习任务
- 可接受/可延后/可关闭/可反馈

**桥接规则**(待设计):
- 电影解说 → 语文阅读/写作素材
- 科普视频 → 科学探究/概念理解
- 体育/游戏 → 数学建模/概率理解

#### 算法3: AI证据绑定式解释(待实现)

**约束规则**:
1. 解释必须引用至少一个`evidence_uri`或时间窗口
2. 不得使用医学、心理诊断、人格评价词
3. 建议必须对应可执行动作

**Prompt结构(待设计)**:
```
输入:证据卡(事实字段) + 任务上下文
约束:三条规则
输出:解释字段(interpretation + action)
验证:引用检查 + 词汇过滤
```

### 3.5 技术创新点总结

**创新1: 统一事件表征框架**
- 学习前(兴趣)、学习中(行为)、学习后(复盘)统一为事件结构
- 每个事件带任务上下文、时间、证据索引、置信度、复核状态

**创新2: 兴趣-知识桥接**
- 从真实生活入口进入可执行学习任务
- 生成可接受、可延后、可关闭的微学习任务

**创新3: 统一时间轴驱动的多模态证据链**
- 标准化事件字段
- 多端数据映射到同一任务时间轴
- 每条解释可回溯到时间窗口、证据来源、复核状态

**创新4: 学习机会窗识别与低置信降级**
- 综合多因素的时机判断
- 证据充分→解释型证据卡
- 证据一般→建议复核卡
- 证据缺失→记录型卡片

**创新5: 证据绑定式AI解释**
- AI只生成解释草稿,不替代教师
- 每条解释绑定时间窗口、证据来源、置信度
- 三条约束规则 + 人工复核框架
