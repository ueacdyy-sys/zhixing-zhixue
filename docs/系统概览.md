# 知行智学系统概览

本文档从用户视角、功能视角和技术视角三个层面完整描述知行智学系统的设计思路、实现状态和技术路线。

---

## 一、用户视角：系统为谁解决什么问题

### 1.1 核心用户群体

**学习者(学生)**
- 遇到兴趣内容(短视频、科普、电影解说)时,不知道如何转化为学习任务
- 学习过程中频繁卡顿、切换、放弃,不清楚问题出在哪里
- 学习完成后只看到结果分数,缺少可回溯的过程证据

**教师**
- 只能看到作业结果和考试成绩,无法获得学生自主学习的连续证据
- 难以判断学生在哪个环节需要引导,在哪里真正理解了
- 过程性评价缺少可复查的客观材料,容易依赖主观印象

**研究者/验证人员**
- 需要小样本、可控、合规的学习分析样例
- 需要验证AI教育应用的可解释性和可追溯性

### 1.2 要解决的核心问题

**问题1: 学习启动断裂 - 兴趣无法进入学习**
学生在日常娱乐时间(刷短视频、看电影解说、科普内容)会遇到很多有价值的概念、表达和问题,但这些兴趣点**几乎从不会**被转化为学习任务。

**为什么不会主动学习?**
- 娱乐状态下,学生不愿意被系统强行拉入正式学习
- 没有明确的学习目标和可执行任务
- 不知道从哪里开始、需要多长时间、能不能放弃

**系统需要做什么?**
识别兴趣中有价值的内容,生成**可接受、可延后、可关闭、可反馈**的微学习任务,让学习从真实生活入口自然发生,而不是强制打断。

**问题2: 过程证据断裂**
即使学生接受了微任务并进入学习,手机、PC、纸笔、视频、EEG/EDA等数据各自孤立,缺少统一的事件字段和时间轴。学习者和教师看不到完整的学习过程线索。

**问题3: 复盘解释断裂**
学习者只看到结果和建议,看不到"系统为什么给出这个建议"、"证据是否充分"、"我在哪个时间窗口发生了策略变化"。

### 1.3 用户使用场景

**核心场景: 从兴趣到学习的完整链路(这才是真实场景!)**

**阶段1: 兴趣触发(手机端,用户授权后采集屏幕流)**
- 学生在手机刷短视频/电影解说/科普内容(娱乐状态,绝不会主动学习)
- 遇到陌生词语/新概念/有趣表达/观点冲突/人物评价
- **系统采集**: 用户授权后,通过RTSP采集**屏幕流视频**(连续媒体+同源音频)
- **视频语义分析**: OCR提取文字,音频转文字,识别内容主题/停留/复看/收藏/搜索
- **兴趣分级**: 
  - L0(CANDIDATE_ONLY): 单帧OCR,无音频,只能save/watch_later/dismiss
  - 语义分析中(SEMANTIC_ANALYSIS_PENDING): 完整视频段+音频,等待分析
  - L1-L4(INTEREST_CONFIRMED): 兴趣确认,可生成学习任务

**阶段2: 兴趣桥接(系统识别,轻量建议,待实现)**
- 系统从视频语义分析结果中提取概念/表达/问题
- 映射到课程知识点(语文/科学/数学/跨学科)
- 生成**微学习任务**: 目标明确、时长5-15分钟、可接受/可延后/可关闭/可反馈
- **核心机制**: 不强制、不打断娱乐、用户拒绝会提高打扰成本
- **L0-L4门控**: 
  - L0候选证据只能保存,不能推练习题
  - L1-L4才能推微任务/练习/测验

**阶段3: 学习承接(如果学生接受,已实现采集层)**
- 学生可能转到**PC**查资料/整理素材/写笔记
  - 系统采集: 前台窗口标题/进程路径/窗口类名(`foreground_window`事件)
  - **不采集**: 屏幕截图/键盘输入/剪贴板/浏览历史
  - 存储: `local://pc/` URI,只保存在本机
- 学生可能拿出**纸笔**书写/阅读课本
  - 系统采集: 摄像头/智能眼镜拍摄**任务相关片段**(不是全程录像)
  - OCR提取文字,视频分析纸笔行为
- 学生可能接入**可穿戴设备**(可选,不强制)
  - EEG/EDA采集状态趋势(相对波动,不做绝对判断)
  - 质量门控: 接触不良/伪迹过多→降级为RECORD_ONLY,不进入解释
  - **禁止操作**: ability_claim/attention_diagnosis/medical_claim/psychological_claim

**阶段4: 过程记录与机会窗识别(核心算法待实现)**
- **统一时间轴**: 手机兴趣事件+PC行为+视频片段+EEG/EDA趋势对齐到同一任务时间轴
  - 同步标记: 任务开始/中途关键节点/结束时记录时间锚点
  - 时间对齐: 同步标记附近误差≤1秒,普通事件≤2秒
  - 冲突处理: 并发事件标记,时间不确定降低窗口置信度
- **学习机会窗识别**(WindowScore评分公式,**核心创新,待研究**):
  - 输入: 兴趣强度×知识相关度×学习缺口价值×状态可接受度 - 打扰成本
  - 窗口类型: 启动窗口/卡顿窗口/策略切换窗口/恢复窗口/复盘窗口
  - 评分依据: 
    - 行为证据(停顿/切换/复看/修改/求助)
    - 任务上下文(阶段/目标/材料)
    - 状态趋势(EEG/EDA相对波动,**仅辅助**)
    - 自评反馈(学生主动报告困难)
  - **待解决**: WindowScore公式需要结合认知负荷理论+心流理论+短视频推荐算法心理机制

**阶段5: 证据卡生成与AI解释(部分实现)**
- **证据卡结构**(已实现基础逻辑):
  - 事实字段: event_id/时间窗口/任务阶段/证据URI/置信度/质量标记
  - 解释字段: 系统判断/AI解释草稿/人工复核状态/降级原因
  - 证据来源: 手机兴趣事件/PC行为/视频片段/自评/EEG趋势
  - 反证信息: 不同证据冲突/证据不足的说明
- **AI解释约束**(待实现):
  - 必须引用时间窗口和证据URI,不能脱离证据生成
  - 禁止使用医学/心理诊断/人格评价词汇
  - 建议必须可执行(回看第2段/补充资料/求助教师),不能是"提高注意力"
  - 证据不足时输出"记录型卡片",不做确定判断
- **降级机制**(已实现):
  - 模态降级: EEG接触不良/视频遮挡→移除该模态
  - 解释降级: 证据不足/AI无法引用证据→只输出候选事件
  - 交互降级: 用户多次拒绝→停止主动触发,只保留任务后复盘

**真实样例(严格按照计划书)**:
> 小明在抖音上看**电影解说**,其中有"人物争议、叙事结构分析、视角转换"  
> → 系统(用户授权后)采集手机**屏幕流视频**,通过**语义分析**识别兴趣  
> → InterestAssessment评估: 兴趣强度中等,与**语文阅读/写作素材/观点表达**相关  
> → 系统生成微任务: "从电影解说理解叙事结构:顺叙/倒叙/插叙(7分钟,可延后/可关闭)"  
> → 小明点"接受" → 系统推送材料(文字+短视频片段)  
> → 小明转到PC查"倒叙和插叙的区别",打开Word整理例句  
> → 系统采集PC窗口切换(浏览器→Word)、搜索词、停留时长  
> → 小明在理解"插叙作用"时停顿30秒,又搜索了"插叙的典型例子"  
> → 系统识别**卡顿窗口**(停顿+资料切换+复看),知识缺口="叙事手法的功能区分"  
> → (可选)如有摄像头:拍到小明在纸上画时间线图  
> → (可选)如有EEG:记录状态波动,但**仅作辅助**,不做能力判断  
> → 任务结束,生成证据卡:  
>   - 兴趣入口: 电影解说视频 `local://phone/interest-session-001`  
>   - 学习行为: PC搜索3次,Word编辑2次 `local://pc/foreground-window-*`  
>   - 卡顿窗口: 10:23-10:25(停顿+搜索"插叙例子")  
>   - 状态趋势: EEG alpha波下降(认知负荷上升),置信度0.65,**仅供参考**  
>   - 证据充分性: 行为证据完整,状态证据辅助,**人工复核建议**  
>   - 复盘建议: "你在理解插叙作用时卡住,下次可以先找3个具体例子对比"

**场景2: 教师过程性评价(待实现,低优先级)**
- 教师查看学生的学习任务证据卡
- 看到学生在哪里卡住、用了什么策略、是否需要引导
- 添加批注、修改复核状态
- 将证据卡作为过程性评价的客观材料

### 1.4 用户价值

**对学习者(核心价值)**
- **降低学习启动门槛**: 从娱乐内容中自然进入学习,不被强制打断
- **看到学习过程**: 理解自己如何进入学习、如何波动、如何恢复,而不是只看到成绩
- **理解困难位置**: 知道在哪个具体时间窗口卡住,而不是模糊的"能力不足"
- **获得可执行建议**: 得到具体的下一步行动(回看第2段/补充资料/求助教师),而不是"提高注意力"这种泛化建议
- **自主控制权**: 可以接受、延后、关闭微任务,不被系统绑架

**对教师**
- 获得可复查的过程材料,减少主观猜测
- 看到学生的努力、困惑和策略变化,而不只是结果
- 用证据支撑过程性评价

**对教育AI应用**
- 提供可解释、可追溯、可复核的AI教育应用范式
- 让AI建议有证据来源,避免黑箱评价
- 通过降级机制处理不确定性,而不是强行给出结论

### 2.2 核心功能模块及实现状态

#### ✅ 已实现的功能

**1. PC学习任务管理**
- 创建PC独立学习任务(无需手机前置)
- 任务阶段管理(观看/阅读/检索/写作/练习/项目)
- 前台窗口事实采集(窗口标题、进程路径、窗口类名)
- 任务时间线生成

**2. 隐私保护采集**
- 只采集窗口元数据,不截图
- 不记录键盘输入、剪贴板、浏览历史
- 本地存储,使用`local://`URI
- 用户显式授权后才开始采集

**3. 统一事件结构**
- 标准化事件字段(event_id, task_id, phase_id, source, modality等)
- 支持多端事件(PC/手机/眼镜/可穿戴)
- 时区感知的时间戳
- 证据URI引用

**4. 质量门控与降级**
- 模态质量评估(FUSION_ELIGIBLE/RECORD_ONLY/EXCLUDED)
- 低质量信号自动降级
- 可穿戴设备只作趋势辅助,不做诊断
- 降级日志完整记录

**5. Android设备连接**
- ADB连接探测
- 设备授权验证
- RTSP媒体传输内核

**6. 手机媒体准入门控**
- 连续媒体+同源音频验证
- 单帧/OCR/无音频只能输出CANDIDATE_ONLY
- 不强制升级为学习结论

**7. PC工作台前端**
- 实时仪表盘(任务状态、采集状态、质量标记)
- 时间线视图(前台窗口变化)
- 任务控制(开始/切换阶段/结束)

### 2.3 手机媒体采集与语义分析流程(核心技术路径)

```
用户授权 → RTSP屏幕流采集 → 连续媒体+同源音频检查
   ↓
admit_full_segment():
  - 检查capture_id存在
  - 检查media_uri以local://开头
  - 检查audio_uri以local://开头  
  - 检查start_ts/end_ts带时区
   ↓
[BLOCKED_INSUFFICIENT_EVIDENCE] → 降级为CANDIDATE_ONLY
   或
[ADMITTED_FOR_SEMANTIC_ANALYSIS] → SEMANTIC_ANALYSIS_PENDING
   ↓
(待实现)慢路径语义分析:
  - 视频OCR提取文字
  - 音频转文字
  - 内容主题识别
  - 兴趣行为分析(停留/复看/搜索)
   ↓
InterestAssessment:
  - 兴趣强度评分
  - 知识点映射
  - result = INTEREST_CONFIRMED
   ↓
可生成L1-L4学习任务
```

**关键代码模块**:
- `analysis/slow_path.py`: admit_full_segment()准入门
- `phone/interest_session.py`: start_interest_session()会话启动
- `phone/keyframe_ocr_candidate.py`: 单帧OCR降级为候选
- `learning/l0_l4_gate.py`: gate_mobile_learning_offer()门控

### 2.5 证据分级机制(严格门控)

**手机媒体分级**:
- **CANDIDATE_ONLY**: 单帧OCR/无同源音频/时间不连续 → 只能save/watch_later/dismiss,**不能生成练习题**
- **SEMANTIC_ANALYSIS_PENDING**: 完整连续媒体+音频 → 进入慢路径分析
- **INTEREST_CONFIRMED**: 语义分析完成 → 可生成L1-L4学习任务

**模态质量分级**:
- **FUSION_ELIGIBLE**: 高质量,可参与多模态融合
- **RECORD_ONLY**: 低质量(signal_quality_low/time_uncertain),只记录不融合
- **EXCLUDED**: 极差(connection_disconnected/evidence_missing),只保留日志

**可穿戴设备限制**:
禁止操作: ability_claim/attention_diagnosis/medical_claim/psychological_claim

### 2.6 降级机制(四级,已实现)

**一级(全证据解释)**
- 兴趣流 + 学习流 + 视频 + 状态趋势

**二级(行为+视频)**
- 移除低质量生理信号

**三级(行为+任务上下文)**
- 移除视频

**四级(记录型证据卡)**
- 只保留事件和自评,不生成自动建议

### 3.4 待实现的核心算法

### 3.5 关键技术决策

**1. 为什么手机必须采集屏幕流视频?**
- 用户在娱乐状态下的兴趣内容**只存在于视频中**
- 单纯行为日志(点击/停留)无法识别"电影解说中的叙事结构"这种语义内容
- OCR+音频转文字→内容理解→兴趣评估→知识点映射

**2. 为什么单帧OCR不能生成学习任务?**
- 单帧没有时间连续性,无法判断"停留/复看/主动搜索"
- 没有同源音频,无法理解完整语义
- 只能标记为CANDIDATE_ONLY,等待完整证据链

**3. 为什么可穿戴设备不能做能力判断?**
- EEG/EDA个体差异大,需个人基线
- 伪迹/接触不良频繁,信号质量不稳定
- **只能作趋势辅助**,不能作主要判断依据
- 禁止ability_claim/attention_diagnosis/medical_claim/psychological_claim

**4. 为什么需要四级降级?**
- 真实场景中设备缺失/质量不稳定是常态
- 降级保证系统在不完美条件下仍能工作
- 记录型证据卡保留过程事实,不强行生成不可靠结论

**5. 为什么AI解释必须引用证据?**
- 大模型容易幻觉,脱离证据评价学生
- 教育场景中误判成本高,需要可追溯
- 证据引用检查: 每条解释必须有evidence_uri或时间窗口
