# 第一人称眼镜摄像头与手机直抓屏幕的取舍

日期：2026-07-07  
用途：判断“在眼镜上装第一人称摄像头拍学生刷手机画面”是否比手机直抓屏幕更适合作为本项目采集路线。  

## 1. 结论

**眼镜第一人称摄像头更适合做过程证据，不适合替代手机直抓屏幕做内容主证据。**

正确关系是：

```text
手机直抓屏幕 = 内容语义主证据
第一人称眼镜摄像头 = 过程状态/现场关系/是否真的在看 的增强证据
```

也就是说，眼镜摄像头不是拿来解决“视频内容是什么”的主问题，而是解决手机直抓屏幕看不到的问题：

- 学生是否真的在看手机；
- 手机是否被放在一边自动播放；
- 手是否在操作，头/视线是否在手机方向；
- 是否从手机转到纸笔、课本、电脑、课堂、聊天、离开；
- 短视频兴趣是否真的进入了后续学习过程。

## 2. 为什么眼镜不能替代手机直抓屏幕

如果只靠眼镜摄像头拍手机屏幕，内容识别会遇到明显工程问题：

| 问题 | 影响 |
|---|---|
| 手机屏幕在画面中占比小 | 字幕、标题、细节难识别 |
| 手抖、走动、低头角度变化 | 画面模糊、透视变形 |
| 屏幕反光、亮度变化、摩尔纹 | OCR和VLM置信度下降 |
| 手机不一定在摄像头中心 | 看得到人和环境，但看不清内容 |
| 第一人称视频抖动强 | 实时处理成本更高 |
| 音频来自环境 | 不等于手机App内部音频，噪声多 |
| 隐私范围扩大 | 会拍到旁人、教室、家庭、聊天内容 |

所以如果目标是“理解当前短视频里的概念、词语、表达、现象、人物和问题”，手机屏幕流仍然更强。

## 3. 眼镜摄像头真正强在哪里

眼镜摄像头强在“过程关系”，不是“屏幕像素”。

| 过程问题 | 手机直抓屏幕能否知道 | 眼镜摄像头能否补强 |
|---|---|---|
| 手机正在播放，但人是否在看 | 不知道 | 可以从手机是否在视野内、头部朝向、场景变化推断 |
| 手机放在一边自动播放 | 只看到视频继续播放 | 可以看到手机离手/不在视野中心/人转向别处 |
| 手在刷，但人是否转头看别处 | 不知道 | 可以看到头部方向和场景，但单摄像头不能精确知道眼球视线 |
| 从手机转向纸笔/课本 | 手机只能看到App退出或停留 | 眼镜能看到纸笔、课本、桌面行为 |
| 课堂/家庭/走路等场景变化 | 手机不知道 | 眼镜能看到现场环境 |
| 是否有真实学习承接 | 手机只能看到后续App | 眼镜能看到纸笔、阅读、电脑、线下材料 |

注意：如果只有第一人称场景摄像头，没有眼动/眼球摄像头，它只能提供“头部朝向和视野代理”，不能严格证明眼睛正在看哪里。要更接近“眼睛是否看手机”，需要眼动摄像头、EOG、IMU或其它状态设备补充。

## 4. 眼镜摄像头应输出什么事件

眼镜摄像头不应输出“学生认真/不认真”这种结论，而应输出低置信过程事件。

推荐字段：

```json
{
  "event_id": "fp_001",
  "source_device": "first_person_glasses",
  "event_type": "view_relation",
  "start_ts": "2026-07-07T16:30:00+08:00",
  "end_ts": "2026-07-07T16:30:08+08:00",
  "phone_in_view": true,
  "phone_screen_visible": true,
  "phone_center_ratio": 0.42,
  "head_motion": "stable",
  "hand_interaction": "swipe",
  "environment_context": "desk_or_classroom",
  "attention_proxy": "likely_phone_view",
  "confidence": 0.63,
  "downgrade_reason": null
}
```

关键字段：

| 字段 | 含义 |
|---|---|
| `phone_in_view` | 手机是否在第一人称画面里 |
| `phone_screen_visible` | 手机屏幕是否可见 |
| `phone_center_ratio` | 手机屏幕在视野中的占比/中心程度 |
| `head_motion` | 头部/摄像头是否稳定 |
| `hand_interaction` | 是否有滑动、拿起、放下等动作 |
| `environment_context` | 桌面、课堂、电脑、纸笔、户外等 |
| `attention_proxy` | 只作为注意代理，不作确定结论 |
| `downgrade_reason` | 模糊、遮挡、离开视野、隐私等 |

## 5. 典型场景判断

| 场景 | 手机直抓屏幕看到 | 眼镜摄像头看到 | 系统判断 |
|---|---|---|---|
| 正常刷视频并看手机 | 视频内容、停留、划走 | 手机在视野中心，头部稳定，手在滑 | 高质量兴趣流 |
| 手在刷但眼睛/头转开 | 视频继续变化 | 手机不在视野中心或头部转向其它方向 | 内容曝光降权，记录 `attention_proxy_low` |
| 手机放一边自动播放 | 视频继续播放、停留很长 | 手机不在手中/不在视野中心/人做别的事 | 不生成兴趣卡，标记 `unattended_autoplay` |
| 打开评论/消息 | 屏幕内容变化 | 可能看到私密界面/输入行为 | 停止内容理解或隐私降级 |
| 从视频转纸笔 | 手机可能停在原画面 | 看到纸笔/课本/书写 | 兴趣可能进入学习承接 |
| 课堂上偷偷刷 | 视频内容可见 | 课堂环境、头部/手部行为 | 合规敏感，必须受控实验，不做泛化监控 |

## 6. 最优架构：双证据源融合

推荐路线不是二选一，而是融合：

```text
手机屏幕流
  -> 内容段、停留、视频语义、兴趣原子

眼镜第一人称流
  -> 手机是否在视野内、是否被观看、是否无人值守、是否转入线下学习

统一时间轴
  -> 对齐 phone_segment 与 first_person_view_relation
  -> 调整兴趣强度和降级原因
  -> 生成证据卡
```

融合规则：

| 手机证据 | 眼镜证据 | 处理 |
|---|---|---|
| 停留长，视频内容清晰 | 手机在视野中心，头部稳定 | 兴趣强度提高 |
| 停留长，视频内容清晰 | 手机不在视野或被放一边 | 降级为自动播放，不生成微卡 |
| 快速划走 | 手机在视野且手在滑 | 记录筛选行为，不理解 |
| 视频停住 | 看到纸笔/课本 | 可能进入学习承接 |
| 手机消息页 | 眼镜也看到私密场景 | 停止内容理解，隐私降级 |

## 7. 眼镜路线的性能指标

| 指标 | 第一阶段目标 |
|---|---:|
| 手机是否在视野内识别 | ≥90% |
| 手机屏幕是否可见识别 | ≥85% |
| 手机中心程度/面积估计误差 | 可用于分级，不要求精确像素 |
| 放一边自动播放识别 | ≥80% |
| 手部滑动/拿起/放下识别 | ≥75% |
| 纸笔/课本/电脑场景识别 | ≥80% |
| 隐私/消息场景漏检 | 0容忍 |
| 眼镜流处理延迟 | P95≤1.5s |
| 与手机屏幕流时间对齐误差 | ≤1s，弱场景≤2s |

## 8. 第一阶段实验怎么做

如果现在没有真智能眼镜，可以先用替代设备模拟：

1. 用手机B或小运动相机固定在胸前/头部近似第一人称视角。
2. 手机A作为被观看的短视频手机。
3. 同时采集：
   - 手机A屏幕流；
   - 第一人称摄像头画面；
   - 统一时间戳或同步拍手/闪屏标记。
4. 跑以下脚本：
   - 正常刷视频；
   - 刷着刷着看别处；
   - 手机放一边自动播放；
   - 从手机转纸笔；
   - 打开消息/评论；
   - 边走边看/桌面看/课堂模拟。

验收目标不是识别视频内容，而是判断：

- 第一人称摄像头能不能可靠说明“人在不在看手机”；
- 能不能识别“无人值守自动播放”；
- 能不能补上手机直抓屏幕缺失的过程证据。

## 9. Go/No-Go 判断

| 判断项 | 结论 |
|---|---|
| 是否用眼镜摄像头替代手机直抓屏幕 | No-Go |
| 是否把眼镜摄像头作为增强模态 | Go |
| 是否用它判断学生注意力/学习能力 | No-Go |
| 是否用它判断过程关系和降级原因 | Go |
| 是否值得后续接入智能眼镜 | Go，但在手机屏幕流通过后接入 |

最终路线：

```text
先攻克手机屏幕流内容理解
再接入第一人称眼镜摄像头做过程证据增强
最后用统一时间轴融合两者
```
