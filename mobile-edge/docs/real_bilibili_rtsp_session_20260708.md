# B站真实刷视频采集与内容理解推进记录 - 2026-07-08

## 本轮目标

在用户已经手动打开手机屏幕流、并处于 B站视频浏览场景的前提下，验证系统能否在不打扰手机操作的情况下完成：

1. 实时屏幕流采集。
2. 关键帧抽样。
3. 视频页与内容主题识别。
4. 字幕/标题/画面证据提取。
5. 兴趣导向微任务闭环样例。

本轮不使用分享链接，不控制手机页面，不通过脚本点击、滑动或切换应用。

## 实验一：真实 B站视频页，RTSP + 去重抽样

输出目录：

`captures/bilibili_rtsp_real_browsing_20260708_180654`

性能结果：

- 实际墙钟耗时：65.11秒
- 解码帧数：1802帧
- 输入帧率估计：30.03 FPS
- PC端解码吞吐：30.47 FPS
- 输出关键帧：21张

判断：

问题：

## 触摸事件结论

两次 RTSP 会话的 `touch_getevent_raw.log` 均为 0 行。

这不能声明“已捕捉全部点击/滑动”。当前只能说明：

1. 视频流采集期间未记录到触摸事件。
2. 可能是用户在这两个窗口内主要停留观看。
3. 也可能是当前 `getevent` 读取方式没有稳定拿到触摸事件流。

后续必须单独做触摸链路验证：在用户明确配合的一次短窗口内，让用户轻点/上滑一次，验证 `/dev/input/event4` 是否输出 `ABS_MT_POSITION_X/Y` 与 `SYN_REPORT`，再写入事件解析器。没有这个验证前，不能宣称“点击、滑动全量捕捉已完成”。

## 本轮微任务闭环样例

触发来源：

用户观看 B站视频 `评论区能玩了！我把弹幕小镇做成了手机单机版`，系统识别到用户对“弹幕/评论区生成虚拟小镇、虚拟居民、人物属性、职业倾向”类内容停留较长。

兴趣主题：

把弹幕或评论从“文字”转化为“居民、事件和规则系统”。

轻量微任务：

**把一条弹幕变成一个居民**

任务时长：2到3分钟。

任务内容：

1. 从“弹幕小镇”的概念出发，选一个你熟悉的短句，例如“别摆烂了”“太抽象了”“我也想住进去”。
2. 把这句话改写成一个虚拟居民的 40 到 60 字人物小传。
3. 小传里必须出现一个“职业倾向”或“性格权重”，例如探索、社交、秩序、创造、冒险。
4. 最后用一句话说明：这条弹幕为什么能变成这个居民？

语文迁移点：

- 拟人化：把抽象评论变成有行动、有性格的人。
- 叙事视角：从“我在评论”变成“一个居民在小镇生活”。
- 说明表达：用规则词解释人物如何被生成，例如“倾向”“权重”“事件”“职业路线”。

反馈标准：

- 是否保留原短句的情绪或语气。
- 是否生成了具体人物，而不是只解释概念。
- 是否出现一个明确的规则词。
- 是否能说清“评论 -> 居民”的转化关系。

这个任务不是刷题，也不是把视频内容硬搬成知识点，而是从视频里的概念延伸出一个低负担表达任务，再迁移到语文表达能力。

## 下一步工程改动

1. 把 RTSP 固定抽样作为主入口：0.5秒一帧进入环形缓冲。
2. 废弃入口整帧去重；改为分层判定：
   - 字幕带文字变化。
   - 标题/作者区低频识别。
   - 画面主体变化。
   - 停留时长。
3. OCR放到异步队列，只跑字幕带或标题区，不阻塞采集。
4. 每个视频段形成 `segment`：
   - `start_time`
   - `end_time`
   - `frame_count`
   - `visible_title`
   - `subtitle_snippets`
   - `visual_summary`
   - `interest_concepts`
   - `task_candidate`
5. 单独验证触摸事件链路。
6. 后续补音频/ASR或端侧音频权限路线，但不能把音频作为当前已完成能力。
