# 完整视频正向学习闭环设计

## 目标

使用手机直接采集得到的完整 canonical 视频及其同源音频，在 PC 上完成连续视频理解、音频转写、时间证据融合、证据卡和兴趣微任务生成，并提供可回放的现场演示界面。

## 不可变边界

- 语义主链输入是完整连续视频片段，不是人工挑选的截图或抽样帧集合。
- 抽样帧、画面变化和 OCR 只属于实时快路径和辅助证据，不能独立打开微任务门。
- 视频、音频、ASR、VLM、证据卡和微任务必须绑定同一 capture_id、原始媒体 SHA-256 和时间范围。
- 微任务是解释、延伸、保存、稍后看和复盘等兴趣探索，不是题目推荐。
- B 站只是首个真实实验场景；业务逻辑不读取或硬编码平台包名。
- 慢速语义分析异步运行，不影响手机浏览。

## 正向演示闭环

1. ScreenStream 直接采集手机正在播放的连续屏幕视频和播放音频。
2. 采集端封存 canonical raw，生成内容摘要和统一时间线。
3. 高质量 ASR 处理完整同源音频，输出带时间戳的转写。
4. 视频模型接收完整 canonical 视频文件，并结合转写理解事件、人物、概念、表达和前后关系。
5. 融合器只接受带时间范围和原始证据引用的语义结论。
6. 证据卡记录来源、时间、视频事件、语音、概念、置信和缺口。
7. 在至少一项真实语义证据达到门槛时，生成一条轻量兴趣微任务。
8. 演示界面可播放原视频、跳转到证据时间段、查看证据卡和微任务。

## 模型路径

- 视频：本地视频多模态模型，工程输入为完整视频文件；模型内部的解码与视觉 token 处理必须在报告中披露，不能称为逐帧无损理解。
- 音频：优先使用 faster-whisper large-v3-turbo；tiny/base 只保留为对照，不用于正向放行。
- 融合：视频模型同时接收完整视频和带时间戳的 ASR 文本，输出严格 JSON。

## 输出契约

- full_video_understanding_report.json：capture_id、media_sha256、model、完整视频路径、处理参数、事件、概念、时间证据、质量说明。
- evidence_cards.json：每张卡至少包含一个视频时间范围和一个语义证据引用。
- microtasks.json：任务类型、兴趣入口、轻量动作、证据卡 ID、production_allowed。
- demo 页面：原视频播放器、时间线、证据卡、微任务、已实测/未验证标识。

## 成功标准

- 使用真实手机采集的完整视频，不使用 fixture 作为演示结果。
- 至少生成一张可回放证据卡和一条非出题式兴趣微任务。
- 人工核看原视频后，证据卡和微任务与视频内容一致；不一致则不得称为可用结果。
- 页面在本机可打开，点击证据可跳转到对应视频时间。
