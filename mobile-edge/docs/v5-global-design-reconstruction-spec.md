# 知行智学 V5 全局设计重构规格

## 结论与边界

当前问题不是若干按钮或配色错误，而是同一产品同时存在三套彼此冲突的前提：网页原型的交互状态、原生 V5 的页面实现、以及真实采集/PC 回传内核。继续逐页补按钮会继续制造重复入口、错误返回与假状态。

本规格确立唯一产品模型。之后网页原型和原生端都必须从该模型实现；网页仅作为已确认视觉层级的参考，不能凌驾于用户已确认的产品职责之上。

已明确排除：耳机设备、人格画像、按时长或通知次数推进 L0–L4、在发现页镜像 L1 系统通知、未配置服务时伪造回答/检索/上传/文件生成。

## 一、唯一的信息架构

底部一级入口固定为：**发现、学习分析、智能体、连接**。`L0–L4` 不是底栏入口，是从发现记录进入的“单次学习路径”；知识全览是学习分析内的一级切换，而非统计图的一个子图。

| 入口 | 只负责什么 | 不得出现什么 |
|---|---|---|
| 发现 | 手机屏幕流/眼镜第一视角的切换；按时间的会话记录；多选、删除、转交智能体 | 采集开关、伪造的实时状态、L1 应用内通知、知识图谱、统计卡片 |
| 单次学习路径 | 当前记录的 L0–L4 自愿学习阶梯；只显示此记录可用的层级 | 长期知识全览、统计图、与本记录无关的节点 |
| 学习分析 | 知识全览图、来源证据、已确认知识的统计分析 | 人格/能力/心理推断；与数据无关的示例折线 |
| 智能体 | 连续对话、资料队列、会话引用、知识库引用、服务配置 | L0–L4 进度、候选审查、设备授权 |
| 连接 | 手机、眼镜、手表、PC 的配对/会话/采集/同步真实状态 | 耳机；重复的“公开媒体会话/媒体会话/会话详情”平行入口 |
| 设置抽屉 | 显示、通知、隐私、网络等低频细项 | 把采集会话、智能体 API、设备配对藏进抽屉 |

### 返回规则

路由状态必须是一个可审计的栈：`root -> secondary page -> detail/canvas`。抽屉是覆盖层，不进路由栈；点遮罩或系统 Back 只关闭抽屉。二级设置返回到打开它的抽屉分组，不允许跳到发现。全屏画布返回它的原页面和原滚动位置。底栏切换清除二级栈，但不篡改发现的选择态以外的业务数据。

## 二、L0–L4 的硬职责

| 层级 | 输入条件 | 允许内容与操作 | 严禁内容 |
|---|---|---|---|
| L0 兴趣点候选 | 当前来源、当前 visit 的证据候选；允许证据不完整 | 兴趣点判断、来源、时间锚点、证据可用性、忽略/保留 | 名词解释、知识图谱、练习、系统强推学习内容 |
| L1 名词解释 | 同一 visit 的完整受控内容包，且学生主动打开 | 一句话定义、必要背景、少量延伸资料 | 图谱画布、习题、把 L1 当作应用内横幅 |
| L2 知识脉络 | L1 可用且学生主动进入 | 当前主题的思维导图或知识图谱、节点笔记、全屏、拖拽、节点边缘 `+` 新建子节点 | 统计图、长期知识库管理、无连接的静态线条 |
| L3 客观练习 | L2 后学生主动开始 | 客观题、作答、即时正确/错误和解释、回执 | 无答案主观题、未提交即给结果 |
| L4 自主作答 | L3 后学生主动进入 | 开放题、草稿、提交、待评阅或基于明确量规的反馈 | 预置标准答案、伪装为已由 AI 评阅 |

L1 仅通过 Android 系统通知通道作“可查看”提示，且只能在当前手机屏幕来源、完整证据、用户允许通知时触发；眼镜第一视角不触发该横幅。通知内容不在发现页再复制一张卡。

## 三、设备、数据与同步模型

设备仅有手机、眼镜、手表、PC。软件连接状态与业务记录必须分离。

1. **手机**：负责屏幕流授权、当前采集状态、发现中的手机来源记录。
2. **眼镜**：负责第一视角视频及时间锚点；外出时可本地封存并向手机传递索引/文件，不能把“已录像”表述成“已实时分析”。
3. **手表**：负责可选状态流，不承担视频；蓝牙连接手机。EEG/EDA 若由穿戴模块提供，连接页显示传感器状态、采样和授权；只有形成有效证据后才在学习分析的来源时间线出现。
4. **PC**：是可选的回家后批量同步、重分析、内容包投递和大文件输出节点，不能成为手机智能体可用的前置条件。

连接页固定为四个独立设备区块；每个区块只展示“连接状态 + 一个主动作 + 一行失败/权限原因”。手机的“公开媒体会话”区块内部顺序固定：`开始/停止屏幕流`、`媒体会话设置`。会话详情并入媒体会话设置，删除平行入口。PC 配对与回传合并为一个区块。

## 四、智能体服务模型：手机是第一等配置端

智能体与学习路径、证据审核、设备授权没有业务耦合；它只接受用户主动带入的会话摘要、资料和知识节点引用。

```text
AgentExecutionMode
├── DIRECT_API      手机直连用户配置的 HTTPS OpenAI-compatible 服务
├── PC_GATEWAY      可选的已配对 PC 服务
└── AUTO            仅在用户明确开启“允许降级”时才按指定顺序尝试
```

智能体服务页必须在手机内提供：

- 运行模式：手机直连 / PC 网关 / 自动；自动的降级顺序可见、默认关闭。
- 手机直连：HTTPS Base URL、模型名、API Key、保存、删除、连通性测试。
- 密钥：只存 Android Keystore 加密密文；不得显示、写日志、进入截图、同步到 PC 或 Git。
- PC 网关：单独显示配对状态、模型状态、可用能力和失败原因；PC 凭据与手机凭据互不复制。
- 能力状态：知识问答、联网检索、资料解析、文件生成分别按当前执行模式的真实能力显示。未实现即“不可用”，不可点亮开关伪装成功。
- 对话页只保留连续消息线程、输入框、附件、联网开关和服务入口。联网开关必须映射到真实能力；它不是“把请求模式改名为 WEB_SEARCH”的视觉开关。

直接 API 的第一期能力只可承诺文本问答和明确返回的 API 错误。联网检索、解析附件、生成 DOCX/PPTX/PDF 必须由服务端能力契约或本地实现逐项声明；不能因为模型接入成功就默认可用。

## 五、知识全览与图谱编辑

“知识全览”汇总手机屏幕流和眼镜第一视角中、经学生确认的知识节点。它与 L2 当前主题图分离：前者是长期个人知识库，后者只服务当前学习内容。

- 节点单击进入节点笔记；只有节点边缘中心的微型 `+` 建立子节点。
- 图谱画布、L2 思维导图、统计图均有全屏入口。全屏图谱必须可拖拽，连线的端点必须锚在节点边缘而不是节点中心或文字中间。
- AI 只能生成“建议变更集”；用户逐项接受、拒绝或编辑后才写入知识库。不得以“同步 AI 生成建议”直接覆盖学生笔记。
- “学习证据 / 证据索引”合并为一个来源证据页；“节点检索 / 关系 / 审核”合并为一个图谱管理页。保留各自二级操作，删除四个平级入口造成的重复。

## 六、当前界面必须删除或重做的内容

1. 删除顶栏中的应用名、智能体名和任何写死时间；系统状态栏已提供时间。
2. 删除所有以解释替代操作的大段说明。正常态每块最多一行状态/失败原因；规则解释只在首次授权、空态帮助或信息按钮内。
3. 删除发现页“最近候选”、固定“正在采集手机屏幕流”等非真实状态。
4. 删除“耳机”设备及其任何配对/状态文案。
5. 删除连接页重复的会话详情入口；合并公开媒体会话、媒体会话设置的层级。
6. 删除原生 `StudentLearningAnalytics` 的确定性锯齿折线和其他与真实数据无关的统计画布；无可解释字段时显示空态，不能填示例数据。
7. 删除旧 `Student*Content` 与 V5 页面并存的运行路径。一个页面只保留一份状态和一套视觉 token。
8. 删除“PC 未配对即智能体不可用”的前提及其相关文案。

## 七、代码重构边界

不得继续扩写 `V5NativeApp.kt`。按变更原因拆成：

```text
v5/
  V5Shell.kt                 Scaffold、底栏、抽屉、唯一 Back 栈
  V5NavigationState.kt       Route、Overlay、scroll restoration、QA fixture
  discover/DiscoverPage.kt   双来源记录、多选、转交
  learning/LearningPathPage.kt
  knowledge/KnowledgeWorkspace.kt
  analytics/LearningAnalyticsPage.kt
  agent/AgentWorkspace.kt
  agent/AgentServiceSettings.kt
  connection/ConnectionPage.kt
  settings/SettingsDrawer.kt
  components/V5Components.kt
```

业务端口必须独立于 Compose：`AgentExecutionPort`、`AgentProviderConfigStore`、`DeviceSessionPort`、`LearningContentPort`、`KnowledgeGraphPort`。`MobileAppServices` 只在应用组合根负责装配，不能继续充当 14 个对象的全局服务定位器。所有持久化状态迁移到具备事务和错误信号的数据层；禁止关键状态用 `SharedPreferences.apply()` 静默失败。

## 八、集中重构的验收门槛

实施顺序固定，禁止再按单个可见问题重新编译：

1. 先把本规格落入网页与原生共享的动作账本：入口、前置状态、动作、目标状态、返回目标、可见失败反馈、真实/Mock 标记。
2. 先完成导航、服务模式、连接会话、L0–L4、知识图谱、资料库的统一状态模型，再迁页面；不在旧 `V5NativeApp.kt` 里叠加分支。
3. 提供 debug-only 的 48 个网页基准状态 fixture，不写真实数据库、不进入 release；生产路径仍只展示真实数据和门控结果。
4. 对所有动作逐条进行原生回放，包含工具栏 Back 和 Android 系统 Back；之后一次构建、安装、冷启动并逐页截图对照。
5. 每个截图以“网页参考状态 / 原生状态 / 合法数据差异 / 未通过项”四栏比对。任何未通过项存在时，不能称 1:1 对齐。

## 九、当前审计结论

当前版本不具备继续堆功能的条件。最先要做的是建立上述共享规格并切断旧 UI、旧状态源与 PC-only 智能体假设；否则每次局部修复都会再次破坏返回链、页面层级或真实能力边界。
