# Implementation Plan: 多入口学习过程证据平台

**Goal**: 在 PC 本地可信中枢上实现可验收的手机兴趣链与 PC/纸笔学习复盘链。  
**Architecture**: 模块化单体部署，按采集连接器、会话授权、事件时间轴、异步分析、证据卡、工作台分边界；云端通过可插拔网关升级。  
**Tech Stack**: 待实施时按真机接口确定；Python 数据处理、DuckDB/Parquet、Web 工作台、OpenCV/ASR/VLM API、MNE/BrainFlow/LSL 为候选，不在本规格阶段冻结。

## Constitution Check

- 多入口：计划必须分别交付 PC 学习、手机兴趣、纸笔/第一视角测试场景。
- 证据优先：所有接口和 UI 从证据索引反向追溯。
- 本地可信：外部模型只能消费单独授权的候选片段或脱敏语义。
- TDD：每一任务先写失败测试，设备协议另有契约测试和真机验收。

## 实施切片

1. 手机会话授权、连续媒体接入、事件协议和删除审计。
2. 手机完整片段慢路径、证据索引、兴趣卡和 L0-L2 自愿承接，这是首个 MVP。
3. PC 本地分析中控台、证据工作台与手机结果回传；PC 学习流采集同时作为第二场景的基础能力。
4. 统一时间轴、窗口和记录型证据卡，覆盖手机与 PC 两场景。
5. 第一视角、手表、EEG/EDA 质量门控与消融。
6. 教师复核、L3-L4、指标、脱敏演示包和 Edge-Cloud 网关。

## 验收前置条件

每一切片都必须提供：样本、事件导出、证据回放、失败/降级日志、自动测试和人工复核记录。任何“实时”“全视频理解”“状态判断”能力均需先标注为待真机验证，未通过不得进入正式演示主张。
