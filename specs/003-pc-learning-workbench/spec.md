# PC 独立学习采集与本地工作台

## 目标

把 PC 从“领域层中的虚拟任务”推进为学生可主动使用的独立学习入口和本地分析中控台。学生可以直接在 PC 看网课、阅读、检索、写作、做题或做项目；系统在明确开始任务后，仅采集前台窗口/进程这一类本机事实，形成可回放的本地证据时间线，并在同一会话中联查手机端已形成的候选卡。

## 用户场景

1. 学生填写目标、学习类型和知识标签，主动开始 PC 学习任务。系统开始采集当前前台窗口的标题、进程标识、进程路径和采样时间；不截屏、不控制第三方应用、不推断专注或能力。
2. 学生在“网课、阅读、检索、写作、练习、项目”之间主动切换阶段。每次切换结束上一阶段、开始下一阶段，时间线保留带时区的阶段边界。
3. 当前台窗口发生变化时，系统把该事实写入仅本机可读的 `local://pc/...` 证据；同一窗口连续保持时不重复写入无意义事件。
4. 学生结束任务后，可查看按真实时间排序的 PC 阶段和前台窗口事实；页面可显示同会话内的手机 `candidate_card.v1`，但不强制把手机候选转为 PC 学习任务。
5. 未来教师端只消费版本化导出契约；本阶段不实现教师登录、教师 UI、远程上传、成绩评定或学习诊断。

## 边界与约束

- 采集只能在学生显式开始 PC 任务后启动，并在显式结束后停止。
- 证据保存为本机 JSON 账本；其 URI 必须为 `local://pc/<session>/...`。窗口标题、进程路径不进入远程服务，也不作为兴趣、知识、专注、能力或心理结论。
- 前台采集适配器是 Windows 实现细节；领域层只接收可追溯 PC 事实事件。
- 手机候选卡必须带版本、会话和候选标识；跨会话卡不可见。
- 手机与 PC 是独立入口。统一时间轴仅按会话、时间与证据引用联查，不建立“手机兴趣必须转 PC 学习”的流程。

## 验收

1. 显式启动任务后，真实 Windows 前台窗口变化会生成一条本地证据文件和时间线事件；未启动任务时不采集。
2. 同一前台窗口的重复采样不重复入账；切换窗口后生成新事件。
3. 阶段切换和结束任务的时间边界可在时间线中回放。
4. 同会话手机候选卡可显示；跨会话候选卡不可显示。
5. 时间线只包含事实、质量和本地证据引用，不包含学习诊断、兴趣结论、练习或强制任务。
