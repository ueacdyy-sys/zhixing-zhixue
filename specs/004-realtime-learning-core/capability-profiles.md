# 能力档位、发布门与真实 UI 接线

本文件防止两种同样错误的交付方式：把一个 build/mock 当成整系统完成；或把云端、眼镜、备份、竞赛等后续能力全部设为本地 PC 核心的前置条件，导致主链永远无法真实运行。

## 1. 档位

| 档位 | 可以真实声称 | 必需门 | 明确不可声称 |
|---|---|---|---|
| `DOMAIN_UI_INTEGRATION` | V5 已接到真实 Room 状态、真实 unavailable/失败状态和真实返回链 | T001–T006、T012–T017、T018–T021、T035–T040、T049–T053、T055、T059–T063 | 不可声称 L1 已真实产生；不得用 fixture/候选卡填充生产页 |
| `LOCAL_PC_L0` | 已配对 PC 的连续媒体产生持久 L0 事实和质量/积压状态 | `DOMAIN_UI_INTEGRATION` + T007、T014、T025、T049–T052、T057 的本地子集 | 不可声称 L1、云、图谱、眼镜、L3/L4 或竞赛闭环 |
| `LOCAL_PC_L1` | 已配对 PC 的稳定语义窗口、真实兴趣、Android 原子落库和低打扰 L1 通知 | `LOCAL_PC_L0` + T008、T015–T016、T026–T027、T031、T054–T055、T058–T060、T062–T065、T070 的本地适用子集 | 不可声称无 PC 云链、眼镜接入、正式作答/L3/L4、受控导出或全竞赛闭环 |
| `CONTENT_GRAPH_L2` | L1 锚点后内容图谱和学生 patch 的渐进生长 | `LOCAL_PC_L1` + T009–T010、T021、T028、T054 | 不可把图谱自动写入长期画像或把外部检索当 L1 依据 |
| `ASSESSMENT_L3_L4` | 已对齐课程资源、独立校验的训练与交卷后复盘 | T022、T033、T045、T058、T061 和相应 TD | 不可在正式作答中介入；不可用未核验/离线未最终化答案 |
| `CLOUD_NO_PC` | 无配对 PC 的 Android 云端连续 L0→L1→撤回删除 | T032、T044、T056、T057、T063、T066、T068–T070 和云端真机证据 | 不可把 unavailable 或聊天 API 称为云端分析 |
| `MULTI_DEVICE_ENHANCED` | 真实眼镜/状态设备按独立 source 加入且安全降级 | T023、T029、T046、T065 和真实设备证据 | 不可把枚举/UI/模拟流称为接入完成 |
| `COMPETITION_EVIDENCE` | 可验证、可复现的能力主张与受控证据导出 | 对应能力档位 + T047–T048、T057、T064、T066、T069 和完整验收包 | 不可把单一正例、构建或截图标为已验证 |

## 2. UI 接线原则

1. `DOMAIN_UI_INTEGRATION` 可以先做，因为它只消费真实持久状态；无分析端、无图谱、无 L3、无云或无眼镜必须显示真实 unavailable/等待/撤回状态。
2. 真正的 L1 生产通知只能在 `LOCAL_PC_L1` 门通过后打开；此前 UI 可以显示 L0、连接、授权、缓存、失败和未接入，但没有样例 L1。
3. 云、眼镜、正式作答、L3/L4、导出和竞赛验收各自独立升级，不阻塞本地 PC L0/L1 的开发和验收，也不能借本地 PC 结果跨档位声明。
4. 同一页面必须从 `CapabilityProfile` 读取当前可用性；不能因代码路径存在、接口可连或调试开关打开就显示“已接入”。

## 3. 发布/报告规则

- 每次演示、验收、竞赛材料和应用设置页都展示当前档位及证据等级。
- 缺少某档位任一必需门时自动降到上一档或 `UNAVAILABLE`；不得保留旧成功缓存作为新能力声明。
- 任一安全、撤回、完整性、策略、时间或协议门失效时，只影响依赖它的档位，不得让无关的 L0 质量记录或 UI 失败状态伪造成功。
